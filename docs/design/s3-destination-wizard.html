S3 destinations: the selector, and the wizard behind it

The engine already talks S3. What is missing is a way to declare a destination without hand-editing config.yaml, and a way to prove one works before it is saved. Panes read left to right, top to bottom. No pane writes anything until the last one.

Whichever of these you pick, what lands in the configuration file is a reference: a path, a variable name, or a command. The four options are the three the schema already accepts, plus an import that turns a pasted key into the first one.

A credentials file already on this machine
AWS shared-credentials format. rclone opens it, so the secret never enters this process at all.
An environment variable
Named here, read at connection time. Nothing about its value is stored.
A command that prints them
An argv array, run directly and never through a shell. This is how a secrets manager gets adopted without this product depending on one.

Declaring a destination moves nothing on its own. Artifacts arrive here only once a retention tier names it, which is a separate decision with a disclosure of its own.

# config.yaml, added storage_mediums: - id: offsite_s3 type: s3 region: us-east-1 bucket: nas-backups prefix: monthly storage_class: STANDARD_IA credentials: file: /etc/backupd/s3_credentials/9b41c7e2 # 0600, written by step 2
There is no access_key_id key here and there is no secret_access_key key here. A configuration file carrying either is a parse error, before validation even runs.
