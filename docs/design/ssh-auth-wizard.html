SSH authentication wizard

Replaces the two write-only text boxes (“SSH key”, “Trusted host key”) that are today the whole of a backup set's SSH editing surface. It offers what is already on the machine, proves it end to end, and only then writes.

“Make it very easy for a brand new user to get rclone authenticated with their SSH server.”

STEP 1 Choose an authentication method that already exists

Nothing here asks anybody to paste a key first. Pasting is the last option on the list, not the only one. Every row is a candidate the NAS can already reach, described by algorithm, fingerprint and where it came from, and never by its contents.

STEP 2 Confirm the server's identity, through the trust model that already exists

The wizard probes the host and compares against what this set's own known_hosts pins. A match moves on with nothing to answer. A mismatch is the same refusal the edit page raises, with both fingerprints, and the wizard cannot get past it without the acknowledgement.
